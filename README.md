# TaskFlow

PWA-менеджер завдань на Vue 3, Framework7, Vite, Pinia та IndexedDB (idb). Практикум 2.10 додає постійне локальне збереження до версії 2.9.

## Запуск і перевірка

```sh
npm install
npm run dev
npm test
npm run build
npm run preview
```

`npm test` виконує 17 тестів: дев'ять перевірок сховищ та вісім перевірок ініціалізації, відновлення, черги збереження, об'єднання змін, відбору даних і помилок. Реальну IndexedDB та офлайн-запуск перевіряють у production preview після активації Service Worker.

## Спільний стан

- `src/store/tasks.js`: завдання, пошук, статус, пріоритет, проєкт, сортування, швидкий фільтр невиконаних, статистика та CRUD.
- `src/store/projects.js`: каталог проєктів, унікальні назви довжиною 3–40 символів, назва за ID та статистика кожного проєкту.
- `src/store/task-validation.js`: спільна перевірка даних форми та дій сховища; не зберігає власного стану.
- Сторінки використовують `storeToRefs()`. Форма, картки та фільтри працюють через Props/Emits.

Збережено категорії, перевірки дат та унікальності назв завдань, попередній перегляд, вибір картки, підтвердження видалення та всі режими сортування. До попередніх завдань додається `projectId: 'general'`.

## Локальне збереження

`src/services/database.js` відкриває `taskflow-db` версії 1 зі сховищами `tasks`, `projects` (ключ `id`) та `metadata` (ключ задається явно). Один знімок обох Pinia-сховищ записується атомарно в одній транзакції. Метадані містять `initialized`, `nextProjectId`, `lastSavedAt`.

`src/services/persistence.js` відновлює дані до `app.mount()`, потім підписується на зміни обох сховищ. Черга об'єднує синхронні зміни й не допускає паралельних записів. Пошук, фільтри й сортування не записуються. На сторінці завдань показано результат транзакції, час останнього збереження і повторну спробу після помилки запису.

Початкові 10 завдань і 3 проєкти створюються лише один раз. Після reload відновлюються власні записи, зокрема порожній список. Якщо базу не вдалося прочитати, застосунок працює в пам'яті з попередженням і не перезаписує наявні дані.

IndexedDB належить конкретному origin та профілю браузера; очищення даних сайту видаляє базу. Автоматичної синхронізації між вкладками або пристроями немає: за одночасного редагування останній знімок може перезаписати попередній. Офлайн-запуск оболонки забезпечує окремо Service Worker; тестуйте `npm run build` і `npm run preview`, спочатку відкривши застосунок онлайн.
